# 유저 스토리

---

## 1. 핵심 시나리오

> **페르소나:** 이서준 (팀장 / PM) — 비개발자, 스프레드시트·슬랙 익숙, CLI 경험 없음

### 하루 시간 순서 시나리오

| 시각 | 상황 | 행동 | 앱에서 하는 일 |
|------|------|------|---------------|
| 09:00 | 출근 직후, 오늘 팀 상태를 파악해야 한다 | 대시보드 접속 | 상태별 집계(할 일·진행 중·완료) 숫자와 **기한 초과** 카드를 한눈에 확인 |
| 09:05 | 기한 초과 일감 2건이 빨간색으로 표시됨 | 일감 목록으로 이동 | 상태 필터 "진행 중" + 마감일 정렬로 초과 일감만 추려서 담당자 확인 |
| 09:10 | 초과 일감 담당자 박민지에게 슬랙으로 공유 필요 | 해당 일감 상세 확인 | 일감 제목·마감일·설명을 보고 슬랙 메시지 작성 (앱 밖 행동) |
| 09:30 | 오늘 새로 들어온 요구사항 3건을 등록해야 한다 | 일감 추가 버튼 클릭 | 제목·설명·마감일·우선순위(높음/중간) 입력 후 저장 × 3 |
| 09:45 | 신규 일감을 팀원에게 나눠야 한다 | 일감 수정 다이얼로그 | 담당자 드롭다운에서 박민지·최하람 지정, 저장 |
| 11:00 | 오전 스탠드업 미팅 준비 | 칸반 보드 열기 | 3개 컬럼(할 일·진행 중·완료)을 보며 각 팀원 진행 상황 구두 공유 |
| 11:15 | 미팅 중 우선순위 변경 요청 발생 | 보드에서 일감 수정 | 일감 카드 수정 버튼 → 우선순위 "중간" → "높음" 으로 변경 |
| 13:30 | 점심 후 오후 작업 배정 확인 | 팀원 관리 페이지 | 팀원별 일감 수 카드로 업무 쏠림 확인 (최하람 1개 ↔ 박민지 5개) |
| 13:40 | 최하람에게 일감 재배정 필요 | 일감 수정 | 박민지 담당 일감 1건 → 담당자를 최하람으로 변경 |
| 16:00 | 고객사 보고 전 완료 현황 점검 | 대시보드 | 완료 숫자와 진행 중 숫자로 오늘 성과 확인 |
| 16:10 | 완료 처리 안 된 일감 발견 | 일감 목록 | 해당 일감 상태를 "진행 중" → "완료" 로 직접 수정 |
| 17:30 | 퇴근 전 내일 우선 처리 일감 정리 | 칸반 보드 | "할 일" 컬럼에서 우선순위 높음 일감 확인 후 담당자 재확인, 이상 없으면 종료 |

### 시나리오에서 사용된 기능 (MVP 5개 매핑)

| 시각 | 사용 기능 |
|------|-----------|
| 09:00 | ⑤ 상태 필터 / 대시보드 집계 |
| 09:05 | ⑤ 담당자·상태 필터 + 마감일 정렬 |
| 09:30 | ① 일감 CRUD |
| 09:45 | ③ 담당자 배정 |
| 11:00 | ② 상태 변경 (칸반 보드) |
| 11:15 | ④ 우선순위 수정 |
| 13:30 | ③ 담당자 배정 (팀원 관리) |
| 16:10 | ② 상태 변경 |
| 17:30 | ④ 우선순위 확인 |

## 2. 결정 사항

| # | 질문 | 선택지 | 영향 범위 |
|---|------|--------|-----------|
| Q1 | **팀장만 일감을 생성·삭제할 수 있는가, 아니면 모든 팀원이 직접 추가·삭제할 수 있는가?** | A) 팀장 전용 / B) 전원 허용 | 권한 모델 — MVP에서 로그인이 없으므로 B가 기본값이나, 실수로 인한 삭제 위험 존재 |
| Q2 | **일감 상태(할 일→진행 중→완료)를 담당자 본인만 바꿀 수 있는가, 아니면 팀장도 대신 변경할 수 있는가?** | A) 담당자 전용 / B) 누구든 변경 가능 | 칸반 드래그·상태 드롭다운 UX 및 16:10 시나리오(팀장이 직접 완료 처리)의 허용 여부 |
| Q3 | **기한 초과 일감은 어떻게 알려주는가 — 대시보드 진입 시 시각적 강조로 충분한가, 아니면 별도 알림(이메일·슬랙 웹훅 등)이 필요한가?** | A) 화면 내 빨간색 강조만 / B) 외부 알림 추가 | MVP 범위 — B는 백엔드·인증 필요, A는 현재 구현으로 충족 |
| Q4 | **한 일감에 담당자를 여러 명 지정할 수 있는가, 아니면 1인만 가능한가?** | A) 단일 담당자 / B) 복수 담당자 | 데이터 모델(`assigneeId` 단일 값 vs 배열), 팀원 관리 페이지의 집계 방식, 필터 UI 복잡도 |
| Q5 | **완료된 일감은 목록에서 기본으로 숨길 것인가, 아니면 계속 표시할 것인가?** | A) 기본 숨김(필터로 다시 표시) / B) 항상 표시 | 일감이 쌓일수록 목록 가독성에 직결 — 팀장 09:05 시나리오(초과 일감 파악)의 노이즈 여부에 영향 |
